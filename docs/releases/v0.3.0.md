# Aries Image Studio 0.3.0

A new architecture. A Rust **Studio** server now owns jobs, history and images, and a
thin **agent** on the GPU host runs the pipeline. Studio can run on any always-on
machine, accepts jobs while the GPU host is off, and every browser sees the same
history. Design: [ARCHITECTURE_V3.md](../ARCHITECTURE_V3.md).

## What changes for you

- **History lives on the server.** Jobs, images, favorites and preferences (including
  the theme) load from Studio. Nothing stays in browser storage, so every browser and
  device shows the same timeline and gallery.
- **One address.** Studio serves the web app, the API and `/metrics` on one port. The
  separate web deployment and reverse proxy are gone.
- **Jobs wait for the GPUs.** Studio queues work while the GPU host sleeps or restarts.
  An agent that reconnects picks up where it left off, and results finished while it was
  disconnected are delivered afterwards.
- **Better use of both cards.** A card keeps its model only while its stage has work
  queued. Otherwise it switches to whatever is waiting, so a denoise backlog runs on
  both GPUs.
- **The enhancer knows the size.** The prompt rewriter is told the job's aspect ratio,
  so a 2:3 job no longer gets a "square-format" description.
- **Every size works.** The ½ and ¼ presets are multiples of 32, which Qwen-Image-2.1
  needs. Before, some of them were quietly cropped and the job then failed.
- **Provenance.** Each PNG carries its full job record in a `tEXt` chunk named
  `aries-image-studio`, including the model revisions and the card each stage ran on.
- **Timeline.** A batch's images sit in a grid instead of a strip that hid some of them,
  long prompts collapse with "Show more", and the phone layout no longer scrolls
  sideways.
- **Monitoring.** Studio's `/metrics` includes each agent's metrics with an `agent`
  label, so Prometheus needs one target.

## Upgrading from 0.2.1

This is a fresh install, not an in-place upgrade. Follow
[BUILD_AND_RUN.md](../BUILD_AND_RUN.md): run Studio from `deploy/studio/`, the agent
from `deploy/aries/`, and give both the same `ARIES_AGENT_TOKEN`.

- History kept in a 0.2 browser is not imported into Studio.
- Initial noise is now drawn on the CPU, so a seed from 0.2 does not reproduce its
  image.
- The `aries_manager` service and its API (`/jobs`, `/status`, `/stage_runs` on port
  8000) are gone. Use Studio's `/api/*` instead.

## Known limitations

- No user authentication: keep Studio on a trusted network. Agents authenticate with
  the shared token.
- Built and tested only on Intel Arc Pro B60 (XPU).
- A stage that is running when its agent restarts counts as a failed attempt, and each
  stage gets two. Update while nothing is running.

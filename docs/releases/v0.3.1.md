# Aries Image Studio 0.3.1

A refinement release on top of 0.3.0: a simpler composer that folds out of the way, a
batch carousel, a viewer that zooms to real pixels, much smaller thumbnails, and an
optional int4 prompt enhancer that needs less than half the card memory.

## What changes for you

- **A simpler composer.** The main row has aspect, size, Draft 12 · Standard 20 ·
  High 40, image count and Enhance. **Advanced** (closed by default) holds custom steps
  (1–100), a fixed seed, VAE tiling and **rows**: each row is a full set of settings
  sent with the same prompt and seeds, to compare steps, sizes or enhanced against plain
  in one send (up to 16 images). A send closes Advanced and resets it, so nothing
  hidden carries over.
- **It folds away.** The composer is a one-line pill until you tap it (full width at the
  bottom on a phone, bottom right on wider screens), and it shows what the next send
  will make. A send, `Esc` or a tap outside folds it again.
- **Random means random.** With Random seed every image gets its own random seed; with
  a fixed seed they count up from it.
- **Rerun and Vary fill the composer** instead of starting a job, with the image's
  prompt and settings (seed locked for Rerun, random for Vary). For an enhanced image,
  an Original · Enhanced switch picks which prompt to use. Rerun used to make the image
  vanish from the timeline without queuing anything.
- **Timeline.** A batch is a carousel at full tile height, in the order the images were
  sent and processed. Sending scrolls to the top, and the page shows a spinner while it
  loads instead of flashing the starter.
- **Viewer.** 100 % is the image's actual size. A zoomed image can be dragged, moved
  with the arrow keys or through the navigator; wheel and pinch zoom at the pointer, a
  click zooms in and out, and previous/next follows the timeline's order.
- **Faster pages.** Thumbnails are JPEGs at 512, 768 and 1024 px (about 40–140 KB
  instead of 1.2 MB), each tile loads the smallest one that is sharp, and the browser
  caches images.
- **Faster half-size images.** Only full-size decodes are still limited to one at a
  time; ½ and ¼ sizes decode on both cards at once.
- **Smaller enhancer, optional.** The agent can run the prompt enhancer from a torchao
  int4 checkpoint: 7.9 GiB peak instead of 17.4 GiB, and 33 tok/s instead of 20. How to
  make it: [BUILD_AND_RUN.md §3](../BUILD_AND_RUN.md#3-download-the-models-gpu-host).
- **Per-job VAE tiling**, off by default, for when speed or memory matters more than a
  seamless decode.
- **Agent health.** `/healthz` and `/readyz` on the agent's metrics port, and a Compose
  healthcheck.

## Upgrading from 0.3.0

An in-place upgrade: pull both images and restart Studio and the agent, while nothing is
running. History, images and preferences carry over.

- Update the agent along with Studio: per-job tiling needs an agent that declares the
  tiled decode, and Studio refuses a tiling job otherwise.
- Copy the new `deploy/aries/compose.yaml` to get the agent's healthcheck.
- Thumbnails of earlier images are made the first time they are shown, and the old
  WebP thumbnails are deleted when Studio starts.
- `POST /api/jobs` accepts 1–100 steps (`422` otherwise) and defaults to 20. A retry of
  a job that is not failed or cancelled is answered with `409`.
- To use the int4 enhancer, quantize it once with the new agent image and point
  `ARIES_ENHANCER_MODEL_PATH` at it. Without that the agent keeps using bf16.

## Known limitations

Unchanged from 0.3.0: no user authentication (keep Studio on a trusted network), built
and tested only on Intel Arc Pro B60 (XPU), and a stage running when its agent restarts
counts as a failed attempt.

# Aries Image Studio 0.4.0

Reference images, an enhancer that can read them, and full-size jobs that stay inside
the hardware: full-size decodes need half the card memory and no longer spill into host
RAM, and memory-heavy work can no longer take the desktop session down.

## What changes for you

- **Reference images.** Attach up to 4 images to a prompt (the attach button, a drop
  anywhere on the page, a paste, or "Use as reference" on any result) and refer to them
  as "image 1", "image 2", … to edit or combine them. The composer shows them numbered,
  to remove or reorder; turns and the viewer show them; Rerun and Vary bring them back.
  Each reference is VAE-encoded once and stored, so later images reuse it.
- **Enhance with references.** With the image-aware enhancer Qwen-Image-2.1-PE-I2I
  installed, Enhance stays available while references are attached: it reads the images
  with your instruction and writes a precise edit prompt. Without it, Enhance is off
  while references are attached.
- **Enhanced prompts that finish.** The enhancer's token limit defaults to 4096 plus 2048
  per reference image. Reasoning that runs out of room continues with the limit doubled,
  up to 24,576, instead of returning its unfinished reasoning (or "…") as the prompt.
  You can set the limit under **Advanced**, and the viewer shows tokens used against it.
- **Full-size decodes: half the memory, same pixels.** The decoder's attention runs on
  the whole image and its upsampling in two overlapping strips: 11.6–12.5 GiB on the card
  instead of 25.8, ~0.1 GB of host RAM instead of 13–17 GB, pixels within 1/255 of a plain
  decode, ~5 s. Full-size decodes no longer have to wait for each other.
- **No more logouts under load.** Four full-size images with references once ended in an
  out-of-memory kill that took the desktop session with it. Now the kernel always picks a
  stage worker (its task is retried), the agent's RAM guard reacts within 0.25 s, and the
  tasks that do spill into host RAM (denoise with 3 or more references, a plain untiled
  full-size decode) take turns across both cards.
- **Steadier under failures.** Identical images or embeds from two jobs no longer lose
  their shared file; a result Studio cannot record is retried instead of leaving a card
  idle until the agent reconnects; releasing a card while it uploads no longer confuses
  its state.

What was changed and measured: [OPTIMIZATIONS.md](../OPTIMIZATIONS.md).

## Upgrading from 0.3.1

Pull both images and restart Studio and the agent, while nothing is running. History,
images and preferences carry over; Studio adds its new tables and columns on start.

- **Update the agent together with Studio.** Reference images, the per-job token limit
  and the image-aware enhancer need both, and Studio refuses references until the agent
  declares them. Mixed versions otherwise keep working.
- **Optional: the image-aware enhancer.** Download Qwen-Image-2.1-PE-I2I next to the other
  models (`qwen-image-2.1-pe-i2i`), preferably as an int4 copy (~10 GiB on the card, about
  2 minutes a job; BUILD_AND_RUN.md §3), and copy the new `deploy/aries/compose.yaml`,
  which mounts it. The agent ignores the path until the model is there.
- **New agent settings**, all with working defaults: `ARIES_DECODE_SPLIT_ABOVE_PX`
  (3.5 MP; `0` for plain untiled decodes), `ARIES_MAX_REFERENCE_IMAGES` (4),
  `ARIES_DENOISE_REFS_LIMIT_ABOVE` (2), `ARIES_RAM_GUARD_FLOOR_BYTES` (4 GiB),
  `ARIES_WORKER_OOM_SCORE_ADJ` (1000). See BUILD_AND_RUN.md.
- **API:** `POST /api/uploads` and `references` on `POST /api/jobs`;
  `enhance_max_tokens` (256–24576) on `POST /api/jobs`; `max_references_*` and
  `enhance_max_references_*` in `/api/capabilities`.

## Known limitations

Unchanged from 0.3.1: no user authentication (keep Studio on a trusted network), built
and tested only on Intel Arc Pro B60 (XPU), and a stage running when its agent restarts
counts as a failed attempt. The enhancer's "keep image N's aspect" answer is stored but
not used yet.

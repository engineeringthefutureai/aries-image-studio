# Aries Image Studio 0.5.0

Cloud prompt enhancers for quick drafts, an app where every page has its own link and
long histories load as they scroll, and a round of fixes from two code reviews.

## What changes for you

- **Cloud prompt enhancers, off by default.** With an API key in Studio's environment,
  a picker next to Enhance offers Claude Sonnet 5.5 and Gemini 3.5 Flash-Lite besides
  the built-in enhancer. They rewrite a prompt in 8–20 s without using a card, against
  30–40 s on a card for the built-in one: a 4-image draft batch took about 50 s instead
  of 2 minutes ([CLOUD_ENHANCERS.md](../CLOUD_ENHANCERS.md) §5 compares them on one
  prompt). They read reference images too. Built-in stays the default and the only one
  that works offline. The prompt and any reference images go to the provider you pick,
  under its terms. A failed cloud rewrite fails the job visibly, and the card offers
  **Built-in** next to Retry.
- **Every page has its own URL.** The timeline (`/`), the gallery with its filters
  (`/gallery?fav=1&aspect=16:9&q=…`), each image (`/images/{id}`) and the system view
  (`/status`) can be bookmarked, shared and opened in new tabs; Back and Forward work.
  The viewer is a page, not an overlay, so scrolling it no longer scrolls the timeline.
- **Long histories stay fast.** The timeline and the gallery load 40 jobs at a time as
  they scroll; with 200+ images the app used to load 2.5 MB and render everything at
  once. The gallery's search and filters run in Studio, so they cover every image.
- **Deleting an image asks first.** Enter confirms, Esc cancels.
- **Edits with reference images no longer fail at denoise** when Studio is reached over
  a slower link: the agent could hand a worker its task before the inputs had arrived.
- **Steadier after network blips.** An agent that reconnects no longer gets a job its
  loaded enhancer refuses (which disabled the card), no longer loses its message
  channel to a racing cleanup, and its running tasks are no longer reclaimed moments
  after a second disconnect. A Cancel during an input download now cancels.
- **Retry works days later.** Retrying a failed job after the intermediate cleanup
  re-runs the stages whose outputs are gone, instead of failing again.
- **Images are right from the first fetch.** An image fetched in the instant after its
  job finished could be cached for a year without its provenance; prompts in Chinese or
  with emoji are now readable in the PNG metadata in other tools.

## Upgrading from 0.4.0

Pull both images and restart Studio and the agent, while nothing is running. History,
images and preferences carry over; Studio adds its new column on start.

- **Cloud enhancers (optional):** set `ARIES_CLOUD_ENHANCERS=on` and `ANTHROPIC_API_KEY`
  and/or `GEMINI_API_KEY` in Studio's environment, keys as secrets. Studio then needs
  outbound HTTPS to `api.anthropic.com` / `generativelanguage.googleapis.com`. Limits and
  models have defaults; see CLOUD_ENHANCERS.md §6 and BUILD_AND_RUN.md.
- **Agent:** no new settings. `ARIES_MAX_REFERENCE_IMAGES`, if set, must be 0–10 (the
  model's limit); the agent refuses to start above it.
- **API:** `POST /api/jobs` takes `enhancer`; `/api/capabilities` lists
  `cloud_enhancers`; `POST /api/jobs/{id}/retry` takes an optional `{enhancer}`;
  `GET /api/jobs` pages with `limit` and `before` (and `status`, `favorite`, `q`,
  `aspect`), and job lists leave out the enhancer's reasoning (`has_thinking`; fetch
  it from `GET /api/jobs/{id}`); `GET /api/gallery/facets` gives the filter counts.

## Known limitations

Unchanged from 0.4.0: no user authentication (keep Studio on a trusted network), built
and tested only on Intel Arc Pro B60 (XPU), and a stage running when its agent restarts
counts as a failed attempt. Images written before 0.5.0 keep raw UTF-8 in their PNG
metadata.
